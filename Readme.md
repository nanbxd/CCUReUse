# CURU — Caspian University Re-Use

Платформа бесплатной передачи вещей между студентами Caspian University. Стек: **React + Vite**, **FastAPI + SQLAlchemy**, **aiogram 3**, SQLite локально и PostgreSQL при размещении на Render.

## Возможности

- Каталог с категориями и поиском, подробные карточки с описанием, состоянием, местом передачи и контактом владельца.
- Лента новых публикаций, регистрация и вход, личный профиль со статистикой и управлением объявлениями.
- Публикация вещей с фото до 2 МБ (JPEG, PNG, WebP), смена статуса на «забронировано» или «передано».
- Telegram-бот: выбор категорий командой `/start` без аккаунта на сайте, уведомления о новых объявлениях и при желании связь с профилем CURU.
- Поддержка через Telegram-бота: обращения пользователей и ответы команды в отдельном чате.

В базе при первом запуске появляются **демонстрационные** объявления. Они нужны для просмотра интерфейса; у них нет реального контакта. Выключить их можно через `SEED_DEMO=false` до первого запуска с пустой базой.

### Вход для команды CURU

Задайте `ADMIN_PASSWORD` (не менее 12 символов) в `backend/.env` локально или в переменных окружения Render. По умолчанию администратором становится существующий аккаунт `demo@curu.local` («Команда CURU»). При запуске сервер задаёт ему указанный пароль и роль администратора; если аккаунта ещё нет, он создаётся. Затем откройте страницу входа, выберите «Вход» и используйте этот email и пароль. Раздел «Админ» показывает все объявления и позволяет удалить любое из них. Не храните пароль в репозитории. При изменении `ADMIN_PASSWORD` и перезапуске сервера пароль аккаунта обновится.

## Локальный запуск

Нужны Python 3.11+ и Node.js 20+.

### API

```powershell
cd backend
python -m venv .venv
.\.venv\Scripts\Activate.ps1
pip install -r requirements.txt
Copy-Item .env.example .env
uvicorn app.main:app --reload
```

API: <http://localhost:8000>; документация Swagger: <http://localhost:8000/docs>.

Для проверки API: `pip install -r requirements-dev.txt`, затем `python -m unittest discover -s tests -v` из папки `backend`.

### Сайт

В другом терминале:

```powershell
cd frontend
npm install
Copy-Item .env.example .env
npm run dev
```

Сайт: <http://localhost:5173>.

## Подключение Telegram

1. Создайте бота у [@BotFather](https://t.me/BotFather).
2. Укажите в `backend/.env` его токен `BOT_TOKEN` и имя без `@` в `BOT_USERNAME`.
3. Перезапустите API. Откройте бота в Telegram и нажмите Start: он сразу покажет кнопки категорий. Отметьте нужные — бот будет присылать новые объявления из них. Команда `/categories` снова откроет настройки, а нижняя кнопка включит или выключит уведомления.
4. Если нужно связать Telegram с аккаунтом CURU, используйте кнопку «Подключить бота» в профиле. Выбранные в боте категории сохранятся. Ссылка действует 15 минут; если истекла, обновите страницу профиля.

### Поддержка в Telegram

1. Добавьте бота в отдельную группу команды или откройте с ним личный чат. В этом чате отправьте `/chatid` — бот ответит ID (у группы он обычно начинается с `-`).
2. Укажите этот ID в `SUPPORT_CHAT_ID` рядом с `BOT_TOKEN` и `BOT_USERNAME` (в `backend/.env` локально или в переменных окружения Render), затем перезапустите API.
3. На сайте появится ссылка со страницы «Поддержка» на бота. Пользователь отправляет вопрос после `/support` или перехода по ссылке; сообщение приходит в чат команды. Ответьте реплаем на сообщение бота, и он доставит ответ пользователю. Команда `/cancel` завершает отправку сообщений в поддержку.

Уведомления отправляются только другим пользователям, у которых включена нужная категория. Для работы бота в этом варианте сервер API запускается **одним процессом**: aiogram работает в том же процессе через long polling. Несколько процессов с одним токеном конфликтуют.

## Размещение на Render и Vercel

1. Загрузите репозиторий в GitHub.
2. В Render создайте **Blueprint** из `render.yaml`. Он создаст Python web service и PostgreSQL. В переменную `FRONTEND_URL` укажите будущий адрес Vercel, например `https://curu.vercel.app` (без `/` на конце).
3. В Vercel импортируйте тот же репозиторий, выберите **Root Directory: `frontend`**. Framework Preset: Vite; Build Command: `npm run build`; Output Directory: `dist`.
4. В Vercel добавьте переменную `VITE_API_URL=https://curu-api.onrender.com` (укажите фактический адрес сервиса Render), затем сделайте redeploy.
5. Если адрес Vercel поменялся, обновите `FRONTEND_URL` в Render. Для нескольких адресов допустима строка через запятую.
6. В Render добавьте `BOT_TOKEN`, `BOT_USERNAME` и `SUPPORT_CHAT_ID`, затем перезапустите сервис.

`frontend/vercel.json` обеспечивает работу прямых ссылок на карточки и другие страницы React. `DATABASE_URL` автоматически передаётся приложению из Render PostgreSQL. `JWT_SECRET` генерируется Blueprint автоматически.

**Для постоянно работающих уведомлений бота нужен сервер Render без засыпания.** Бесплатный web service может засыпать, из-за чего long polling бота временно останавливается. Бесплатный PostgreSQL Render также имеет ограничения по сроку и объёму; перед реальным запуском выберите устойчивый план или другую постоянную БД.

## Модерация объявлений

Задайте `MISTRAL_API_KEY` ключом из [Agnes API Platform](https://platform.agnes-ai.com/settings/apiKeys). Имя переменной сохранено для совместимости. Также нужны `BOT_TOKEN` и `SUPPORT_CHAT_ID`; без них API не принимает новые объявления. В Render эти значения задаются как переменные окружения сервиса.

При создании объявления Agnes проверяет текст и фотографию. Допустимые вещи публикуются сразу. Взрослый, запрещённый, посторонний или не совпадающий с фотографией контент получает статус «На модерации» и не виден в каталоге или по прямой ссылке. Бот отправляет фотографию, описание и причину в `SUPPORT_CHAT_ID` с кнопками «Разрешить публикацию» и «Удалить». В группе эти кнопки доступны только администраторам Telegram; в личном чате — владельцу чата. Администратор сайта также может принять или удалить объявление на странице управления. Если Agnes временно недоступен, объявление остаётся на ручной проверке.

## Что учесть перед открытым запуском

- Регистрация сейчас по любому email, без проверки студенческого статуса. Перед запуском только для студентов нужно добавить подтверждение университетской почты или интеграцию с университетской авторизацией.
- Контакты из профиля и карточки публичны. Пользователям стоит указывать контакт, который они готовы показывать другим.
- Фото сохраняются прямо в БД. Для большой аудитории лучше перенести их в объектное хранилище, например S3 или Cloudinary.
- Внешние фотографии демонстрационных объявлений загружаются с Unsplash; для реального каталога пользователи загружают свои фото.

Интерфейс CURU выполнен в белой и оранжевой палитре как отдельный студенческий продукт.

## Caspian Events

Модуль мероприятий использует аккаунты CURU и отдельные таблицы `events`, `tickets`, `reviews`, `event_interests`, `event_notifications`. При старте приложения новые таблицы создаются автоматически, в `users` добавляется `is_organizer`. Для установок под управлением Alembic добавлена миграция `e20261019events`: `alembic upgrade head` из каталога `backend`. Перед обновлением рабочей базы сделайте резервную копию.

- `/events` — публичная афиша, фильтры по типу. `/events?archive=true` — архив; фильтрация по организатору также доступна со страницы события.
- `/events/new` — предложение идеи. Обычный студент создаёт только бесплатную приватную встречу. Приватные события доступны по UUID-ссылке и не включаются в публичную афишу/архив.
- `/organizer` — свои мероприятия, запуск регистрации или сбора со сметой и реквизитами доверенного лица, проверка чеков, список возвратов, сканер входа. Администратор здесь выдаёт и отзывает роль организатора по ID пользователя. ID виден в ссылке на публичный профиль; после выдачи роли пользователь обновляет страницу.
- `/profile/tickets` — билеты, уведомления об исходе сбора и QR для подтверждённых мероприятий. QR скрыт до успешного сбора и после использования/отмены.

Цена и бюджет задаются целыми тенге; минимум билетов округляется вверх. Вместимость учитывает и ожидающие проверки бронирования. Каждый пользователь может забронировать один билет на событие. Повторное выражение интереса не увеличивает счётчик. Чеки JPEG/PNG/WebP до 2 МБ хранятся в БД и выдаются только организатору/администратору.

Фоновая задача каждые 30 секунд завершает сборы и мероприятия; перед чтением афиши/билетов и критическими операциями сроки также проверяются. После остановки сервера пропущенные переходы выполняются при следующем запуске. Даты хранятся и возвращаются в UTC, формы/отображение используют часовой пояс устройства.

Оплата и возврат через Kaspi **ручные**. Статус `refunded` при отмене означает включение оплаченного билета в процесс возврата; отдельное поле `refund_completed` устанавливает организатор после фактического перевода. Непроверенные чеки также доступны в списке отменённого события. Уведомления сохраняются внутри сайта в разделе билетов; браузерные push-уведомления не подключены.

`POST /api/tickets/verify` доступен создателю события или администратору и атомарно переводит оплаченный билет в `used`. Повторный проход отклоняется с временем первого прохода. Камере нужен HTTPS (или localhost), разрешение пользователя и поддержка камеры устройством. Есть ручной ввод QR-хэша. Отзыв может оставить только участник с использованным билетом после завершения события, один раз.

Проверка модуля из корня проекта:

```powershell
$env:PYTHONPATH = "$PWD/backend"
python -m unittest discover -s backend/tests -p test_events.py -v
```

Для локального SQLite задайте `DATABASE_URL=sqlite:///curu.db` и `JWT_SECRET`. PostgreSQL по-прежнему можно настроить через `DB_USER`, `DB_PASSWORD`, `DB_HOST`, `DB_PORT`, `DB_NAME` либо `DATABASE_URL`. Дизайн и адаптивные правила описаны в `DESIGN.md`.
